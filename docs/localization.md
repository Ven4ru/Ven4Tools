# Язык интерфейса

Клиент и лаунчер работают на русском и английском. Русский — язык исходных текстов:
он записан прямо в коде и разметке. Английский — отдельный файл перевода (языковой
пакет), который подставляется при показе.

## Как это устроено

- **Русская строка — она же ключ.** В коде и XAML пишем по-русски, как раньше.
  Ресурсных файлов и идентификаторов строк нет.
- **Таблица переводов** — `Localization/en.json`: пары «русская строка → английская».
  Строки с подстановками записаны шаблоном: `Установлено: {0}, ошибок: {1}`.
- **Языковые пакеты** — `Localization/packs/client-en.json` и `launcher-en.json`.
  Их собирает `Tools/LanguagePackTool` из таблицы: в пакет программы попадают только
  те строки, которые есть в её исходниках. Файлы лежат в репозитории.
- **Подстановка при показе** — `Shared/Localization`. Почти весь текст WPF рисует
  `TextBlock`; при первой раскладке элемента и при каждой смене текста строка ищется в
  пакете: целиком, затем по шаблонам, затем построчно. Так же обрабатываются заголовки
  окон, поля только для чтения, сообщения `MessageBox` и имена элементов для экранных
  дикторов.
- **Пакет привязан к сборке.** Контрольная сумма пакета вшивается в программу при
  сборке, и программа принимает только свой пакет — откуда бы он ни пришёл.

## Откуда программа берёт пакет

1. Профиль пользователя: `%LOCALAPPDATA%\Ven4Tools\lang\`.
2. Папка программы: `lang\en.json` (туда пакет лаунчера кладёт установщик, если при
   установке выбран английский; сборка для разработки кладёт его туда сама).
3. Сеть: `cdn.ven4tools.ru/releases/lang/`, затем зеркало `ven4tools.ru/releases/lang/`,
   затем файл релиза на GitHub.

Русскому языку файл не нужен. Пакет клиента лаунчер скачивает заранее — сразу после
установки или обновления клиента, если выбран английский.

Выбор языка один на установщик, лаунчер и клиент: значение `Language` (`ru` или `en`)
в `HKCU\Software\Ven4Tools`. Значения нет — язык берётся по языку Windows: русская
система — русский, любая другая — английский. Язык меняется при запуске программы.

## Добавили или изменили русскую строку

Модульные проверки (`LanguagePackCompletenessTests`) не пройдут, пока у строки нет
перевода, а пакеты не пересобраны.

```powershell
# 1. Заготовка: строки без перевода с пустым полем "t"
dotnet run --project Tools/LanguagePackTool -- missing . missing.json

# 2. Заполнить переводы в missing.json и внести их в таблицу
dotnet run --project Tools/LanguagePackTool -- merge . missing.json

# 3. Пересобрать пакеты (--strict: ошибка, если что-то осталось без перевода)
dotnet run --project Tools/LanguagePackTool -- pack . --strict
```

`missing.json` в репозиторий не кладём. В коммит идут `Localization/en.json` и оба
пакета вместе с изменением исходников.

Требования к переводу (их проверяет `merge` и модульная проверка):

- те же подстановки `{0}`, `{1}`, что в исходной строке (порядок менять можно);
- столько же строк и те же пробелы по краям;
- термины — как в остальном переводе: «набор» — set (в каталоге) и kit («Перед
  переустановкой»), «твик» — tweak, «лаунчер» — launcher.

## Строки, которые переводить не нужно

Русский текст, который человеку не показывается (слова для поиска, заголовки столбцов
вывода winget, шаблоны разбора), перечислен в `Localization/ignore.json`. Туда же —
сообщения, намеренно написанные сразу на двух языках.

## Где перевод подставляется вручную

Текст, который показывает не WPF, оборачивается в `Tr("…")`:

- подписи системных окон выбора файла и папки (`Title`, `Filter`, `Description`);
- меню и подсказки значка в области уведомлений;
- имена и содержимое файлов, которые программа пишет для человека;
- вывод в консоль.

`MessageBox.Show` оборачивать не нужно: это имя во всём проекте указывает на обёртку
с переводом.

## Как проверить

- `VEN4TOOLS_LANG=en` (или `ru`) — язык на один запуск, без записи в настройки.
  Проверки интерфейса закрепляют русский сами.
- `VEN4TOOLS_L10N_COLLECT=<файл>` — в файл складываются русские строки, которым на
  экране не нашлось перевода. При русском интерфейсе текст не меняется, только
  сверяется с пакетом — так обычный прогон проверок интерфейса находит пропуски.
- Снимки всех разделов на выбранном языке — проверка
  `ScreenshotGeneration.СделатьСнимкиВсехРазделов` (категория `LanguageTour`).

## Выпуск

Пакет выкладывается вместе с релизом — ровно тот, с которым собрана программа.

```powershell
# клиент: после dotnet publish
.\Tools\export-language-pack.ps1 -Component client -Version X.Y.Z -Binary .\_release\client_XYZ\Ven4Tools.dll
```

Для лаунчера то же делает `build_installer.ps1`. Скрипт сверяет пакет со сборкой и
кладёт его в `_release` под публикуемым именем; `Tools\deploy-cdn-release.ps1` заливает
его на CDN вместе с архивом клиента или установщиком. Тот же файл прикладывается к
релизу на GitHub.
