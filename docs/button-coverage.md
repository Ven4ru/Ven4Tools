# Реестр кнопок и покрытие живым кликом

Составлен 19.08.2026. Цель — заменить ощущение «тестов много» на цифру, которая не врёт.

## Зачем не «100% покрытия»

Часть кнопок кликать нельзя ни при каком бюджете времени, и это не недоработка:

* **физически невозможно** — нативные диалоги ОС (открытие/сохранение файла) принадлежат оболочке, а не приложению; UAC рисуется на secure desktop, куда Windows намеренно не пускает программный ввод;
* **разрушительно** — реальный клик удаляет пакеты (`Remove-AppxPackage`), ставит Office, перезагружает компьютер, меняет питание процессора или создаёт issue в публичном репозитории.

Поэтому осмысленная цель — **100% от множества «должно кликаться»**, а остальное закрыто явным вердиктом, а не молчанием.

## Итог

| | Всего | Должно кликаться | Покрыто | Только код-ревью | Физически невозможно |
|---|---|---|---|---|---|
| Клиент | 137 | 108 | **76 (70%)** | 20 | 9 |
| Лаунчер | 18 | 12 | **7 (58%)** | 5 | 1 |

Динамических точек генерации кнопок в клиенте — 3 (строки каталога, пины, подсказки поиска); они порождают в рантайме много экземпляров одного шаблона и в таблицу как отдельные кнопки не считаются.

⚠️ **Цифра «покрыто» — нижняя оценка.** Она собрана автоматически по `ByAutomationId` и по видимому тексту в тестах. Кнопки, которые тест нажимает обобщённым селектором (например, единственную кнопку в модальном диалоге через `ByControlType(Button)`), детектор не видит. Пример: «Сохранить» в `PresetSaveDialog` реально нажимается тестом пресетов, но в реестре числится непокрытой.

## Клиент — только код-ревью, кликать нельзя (20 кнопок)

| Кнопка | Почему |
|---|---|
| Карточка: «Установить», «Удалить» | реальный `winget install` / деинсталляция |
| EULA: «Принять и установить» | запускает реальную установку |
| Отзыв: «Отправить отзыв» | реальная отправка на сервер |
| MAS-гайд: «Открыть PowerShell» | запускает внешний процесс |
| Каталог: «Повторить» | повторяет реальную установку |
| Debloater: «Применить выбранное» | `Remove-AppxPackage`, твики служб |
| Диагностика: очистка кэша Windows Update, включение и отключение Turbo Boost | меняют службы и питание процессора |
| «Установленные»: обновить всё, обновить выбранные, удалить выбранные, обновить в строке, удалить в строке | реальные установка и удаление |
| Office: «Скачать», «Установить» | реальная установка Office |
| Настройки: «Скачать выбранные в кэш», «Восстановить» снапшот | большие загрузки, перезапись настроек |
| Результат Windows Update: «Перезагрузить сейчас» | реальная перезагрузка машины |

## Клиент — физически невозможно (9 кнопок)

Нативные диалоги файлов: сохранение отчёта бенчмарка, экспорт и импорт списка в каталоге, экспорт и импорт на «Установленных», два выбора папки и экспорт-импорт настроек в «Системе».

В наборе для этого уже есть явный тест-заглушка `НативныеДиалогиФайлов_ИзвестноеОграничение`.

## Лаунчер (18 кнопок)

**Прокликать (5):** «Пропустить» в окне краш-репорта и в отчёте установки, «Проверить обновления», «Найти клиент на диске», «Закрыть лаунчер».

**Только ревью (5):** «Создать Issue на GitHub» и «Отправить отчёт на GitHub» — создают реальные issue в публичном репозитории; «Обновить лаунчер» — самообновление; «Установить компоненты» и «Удалить клиент» — меняют установку.

**Невозможно (1):** «Установить из файла…» — нативный диалог выбора файла.

## Как поддерживать

Инвентаризация собирается автоматически:

```bash
grep -ro "<Button" Ven4Tools/ --include="*.xaml" | wc -l          # клиент
grep -ro "<Button" Ven4Tools.Launcher/ --include="*.xaml" | wc -l # лаунчер
```

При добавлении кнопки — сразу решить её вердикт. Если «должно кликаться», а теста нет, цифра 70% честно падает; именно это и нужно, чтобы она не превращалась в украшение.
