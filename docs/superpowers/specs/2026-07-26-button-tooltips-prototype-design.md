# Прототип поясняющих подсказок для кнопок

Дата: 2026-07-26
Статус: утверждено пользователем

## Задача

Создать полностью рабочий прототип клиента и лаунчера Ven4Tools, в котором
функциональные кнопки снабжены короткими русскими всплывающими подсказками. Подсказка
должна помочь обычному пользователю до нажатия понять, какое действие будет выполнено
и что оно затронет.

Прототип не публикуется и не смешивается с основной рабочей копией. Он создаётся в
отдельном Git worktree:

`C:\Users\Vench\Documents\GitHub\Ven4Tools-button-tooltips-prototype`

## Границы

В прототип входят:

- WPF-клиент Ven4Tools со всей существующей функциональностью;
- WPF-лаунчер со всей существующей функциональностью;
- подсказки у статических и создаваемых из шаблонов функциональных кнопок;
- единый стиль показа подсказок;
- автоматическая проверка покрытия кнопок;
- сборка и UI smoke обоих приложений.

В прототип не входят:

- публикация, push, PR, tag, release или замена релизных ассетов;
- изменение поведения обработчиков кнопок;
- переработка навигации или компоновки экранов;
- подсказки для флажков, переключателей, полей ввода, ссылок и пунктов меню;
- изменение каталога приложений и его подписи.

## Какие кнопки считаются функциональными

Подсказка обязательна, если кнопка:

- запускает проверку, диагностику, поиск, загрузку, установку, обновление,
  переустановку, удаление или восстановление;
- открывает системную папку, терминал, внешний сайт, диалог выбора либо другое
  функциональное окно;
- сохраняет, импортирует, экспортирует, копирует, отправляет или очищает данные;
- применяет настройку, твик или выбранный набор действий;
- запускает, останавливает или отменяет длительную операцию;
- изменяет порядок, фильтр, набор выбранных элементов либо иное состояние данных.

Подсказка не требуется, если кнопка только:

- переключает раздел главного окна;
- закрывает окно или панель;
- подтверждает закрытие простого диалога кнопкой «Готово»;
- является декоративной частью стандартного элемента управления;
- выставляет оценку звёздами.

Кнопки «Отмена» и «Пропустить» получают подсказку только тогда, когда они прерывают
или пропускают реальную длительную операцию. Обычная отмена диалога в покрытие не входит.

## Тексты подсказок

Каждая подсказка состоит из одного или двух коротких предложений:

1. первое сообщает непосредственный результат нажатия;
2. второе добавляется только для важного последствия, ограничения или риска.

Текст начинается с действия и не повторяет подпись кнопки без новой информации.
Предпочтительная длина — до 140 символов. Технические команды и внутренние названия
упоминаются только тогда, когда они помогают пользователю принять решение.

Примеры:

- «Проверит наличие новой версии клиента и лаунчера. Ничего не устанавливает
  автоматически.»
- «Удалит выбранные приложения после подтверждения. Перед массовой операцией будет
  создана точка восстановления.»
- «Сбросит Winsock и параметры IP. Соединение с сетью может временно прерваться.»
- «Остановит текущую загрузку. Уже загруженные временные данные будут обработаны
  существующей логикой приложения.»

Подсказка не обещает результат, который не гарантирован кодом. Формулировка должна
описывать фактическое поведение соответствующего обработчика или команды.

## Реализация

### Изоляция

От текущего локального `HEAD` создаётся отдельная ветка
`prototype/button-tooltips-20260726` и соседний worktree. Незакоммиченные и
неотслеживаемые файлы основной рабочей копии в прототип не переносятся.

Все изменения XAML, стилей и тестов выполняются только внутри worktree прототипа.
Основная папка `C:\Users\Vench\Documents\GitHub\Ven4Tools` после создания worktree
остаётся без продуктовых изменений этой функции.

### Единый стиль

В ресурсах клиента и лаунчера задаётся общий стиль `ToolTip`:

- перенос длинного текста;
- ограничение максимальной ширины;
- читаемые внутренние отступы;
- задержка перед появлением, не мешающая обычному перемещению курсора;
- увеличенное время показа, достаточное для спокойного чтения;
- цвета из существующей темы приложения;
- отсутствие новой анимации при включённом режиме уменьшенного движения.

Стиль не меняет расположение кнопок и не добавляет рядом отдельные значки.

### Привязка к кнопкам

Для статических кнопок текст задаётся через свойство `ToolTip` непосредственно в XAML.
Так пояснение находится рядом с действием и проще проверяется при дальнейших изменениях.

Для кнопок в `DataTemplate` используется тот же подход; текст должен описывать действие
над элементом текущей строки. Для кнопок, создаваемых программно, подсказка назначается
там же, где создаётся кнопка.

Существующие корректные подсказки сохраняются или уточняются по тем же правилам.

## Проверка покрытия

Составляется машинно проверяемый реестр кнопок в XAML клиента и лаунчера. Для каждой
кнопки фиксируется одно из двух решений:

- функциональная — имеет непустую поясняющую подсказку;
- исключённая — относится к явно перечисленной нефункциональной категории.

Автоматическая проверка должна обнаруживать новую кнопку с обработчиком `Click` или
`Command`, если для неё не задано ни пояснение, ни явное исключение. Динамически
создаваемые кнопки проверяются отдельными существующими или новыми UI-тестами.

## Проверка поведения

Обязательные проверки прототипа:

- `dotnet build .\Ven4Tools.sln -c Release --nologo` — 0 ошибок и 0 предупреждений;
- тест реестра покрытия — у каждой функциональной кнопки есть непустая подсказка;
- проверка, что навигационные и служебные кнопки не получают бессмысленные повторения;
- UI smoke клиента: подсказки появляются при наведении на кнопки основных вкладок;
- UI smoke лаунчера: подсказки появляются на действиях установки, обновления,
  поиска клиента, удаления и отмены загрузки;
- ручная проверка переноса длинного текста, контраста и отсутствия обрезания;
- `git diff --check`;
- проверка рабочего дерева на секреты.

UI smoke не нажимает опасные кнопки и не выполняет установку, удаление, сброс сети или
запуск бенчмарка. Он проверяет только наличие и отображение подсказок.

## Критерии готовности

Прототип готов, когда:

- оба приложения собираются из отдельного worktree;
- каждая кнопка, подходящая под определение функциональной, имеет понятное описание
  фактического эффекта;
- исключения из покрытия ограничены правилами этой спецификации;
- подсказки визуально читаемы и не меняют компоновку интерфейса;
- основная рабочая копия не содержит продуктовых правок прототипа;
- ничего не опубликовано.
