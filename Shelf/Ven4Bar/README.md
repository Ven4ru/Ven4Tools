# Ven4Bar — своя панель задач (заготовка «на полку»)

Отдельный exe (.NET 10, WPF). В клиент Ven4Tools не встроен. Версия 0.1.0.

Правило: только документированные Windows API. Ничего не внедряется в explorer, чужие окна
не скрываются и не двигаются, реверс-инжиниринга нет.

## Что умеет

- **Панель у нижнего края основного монитора**, зарегистрированная как appbar
  (`SHAppBarMessage`: `ABM_NEW` → `ABM_QUERYPOS` → `ABM_SETPOS`, `ABM_ACTIVATE`,
  `ABM_WINDOWPOSCHANGED`). Развёрнутые окна не заходят под неё.
- Реакция на `ABN_POSCHANGED` (пересчёт места) и `ABN_FULLSCREENAPP` (уходит под полноэкранное
  окно, после него возвращается наверх). Смена разрешения и DPI — пересчёт.
- `ABM_REMOVE` при выходе: обычный выход, `ProcessExit`, необработанные исключения
  (`AppDomain.UnhandledException`, `DispatcherUnhandledException`), завершение сеанса.
- **Родная панель задач не трогается.** С флагом `--hide-native` ей включается автоскрытие
  (`ABM_SETSTATE` + `ABS_AUTOHIDE` — то же, что галочка в параметрах). Прежнее состояние
  запоминается в памяти и в `%LOCALAPPDATA%\Ven4Bar\native-taskbar-state.txt`; при выходе
  возвращается, а если программа была убита — возвращается при следующем запуске.
- **Кнопки окон:** `EnumWindows` + фильтр «окна для панели задач»: видимые, без
  `WS_EX_TOOLWINDOW`, без владельца или с `WS_EX_APPWINDOW`, без `WS_EX_NOACTIVATE`, не скрытые
  DWM (`DWMWA_CLOAKED`), с заголовком. Значок — `WM_GETICON` (с `SMTO_ABORTIFHUNG`, 50 мс) или
  значок класса окна.
- Обновление **только по событиям** `SetWinEventHook`: `EVENT_OBJECT_CREATE/DESTROY/SHOW/HIDE/
  NAMECHANGE/CLOAKED/UNCLOAKED`, `EVENT_SYSTEM_FOREGROUND`, `EVENT_SYSTEM_MINIMIZESTART/END`.
  Пачка событий сливается в одно пересчитывание. Опроса окон по таймеру нет.
- Щелчок по кнопке: активное окно сворачивается, иначе — разворачивается и выходит вперёд.
  Свёртывание/разворот — просьбой самому окну (`WM_SYSCOMMAND` `SC_MINIMIZE`/`SC_RESTORE`),
  не `ShowWindow`. Средняя кнопка мыши — закрыть (`WM_CLOSE`).
- **Миниатюра** при наведении (0,4 с): `DwmRegisterThumbnail` в маленьком окне, которое не
  активируется и пропускает мышь.
- **«Пуск»:** если рядом с `Ven4Bar.exe` лежит `Ven4Start.exe` — запускается с `--show`; иначе
  открывается родной «Пуск» сочетанием Ctrl+Esc через `SendInput`.
- **Справа:**
  - часы и дата (таймер, выровненный на начало каждой минуты; подсказка — полная дата по-русски);
  - громкость — Core Audio `IAudioEndpointVolume`: значок по уровню, колесо мыши ±2 %, щелчок —
    выключить/включить звук; изменения извне приходят через `IAudioEndpointVolumeCallback`;
  - язык ввода — `GetKeyboardLayout` потока окна на переднем плане;
  - «^» — показать родную панель (там значки трея): при `--hide-native` временно снимает
    автоскрытие, повторный щелчок — прячет обратно; без флага — Win+B (фокус в область уведомлений
    родной панели, документированное сочетание).
- Значок Ven4Bar в трее и контекстное меню самой панели (правый щелчок) — пункт «Выход».
- Один экземпляр (мьютекс `Local\Ven4Bar.SingleInstance`).

## Чего нет (и почему)

- **Значки трея сторонних программ.** Документированного способа прочитать чужие значки области
  уведомлений нет (все известные способы — чтение внутренних структур explorer). Поэтому «^»
  отправляет к родной панели.
- Группировка окон по приложению, закрепление программ, списки переходов (Jump List) — не делали.
- Несколько мониторов — только основной.
- Смена раскладки внутри одного и того же окна не даёт глобального события; индикатор
  обновляется при смене окна, при щелчке по нему и раз в минуту вместе с часами.
- Смена устройства вывода звука по умолчанию не отслеживается (громкость остаётся на прежнем
  устройстве до перезапуска).
- Окна с правами администратора: из обычного процесса `SetForegroundWindow`/`WM_SYSCOMMAND` к ним
  могут не дойти (UIPI) — так задумано системой.

## Как собрать

```
cd Shelf\Ven4Bar
dotnet build -c Release
```

Результат: `Shelf\Ven4Bar\bin\Release\net10.0-windows\Ven4Bar.exe`.
Запуск: `Ven4Bar.exe` или `Ven4Bar.exe --hide-native`.

На основном ПК не запускалось — проверять в ВМ.

## Что доделать

1. Прогон в ВМ: appbar рядом с родной панелью (с флагом и без), полноэкранная игра/видео,
   аварийное завершение (снять задачу) → следующий запуск возвращает автоскрытие, смена DPI.
2. Отслеживать смену устройства звука (`IMMNotificationClient.OnDefaultDeviceChanged`).
3. Порядок кнопок перетаскиванием, группировка по процессу, закрепление программ.
4. Свой значок приложения (сейчас стандартный), тема светлая/тёмная по системе.
5. Окно календаря по щелчку на часах, ползунок громкости во всплывающем окне.
6. Несколько мониторов (своя панель на каждом, `MonitorFromWindow`).
7. Связка с будущим `Ven4Start.exe` (аргумент `--show`, общий мьютекс/сообщение для повторного щелчка).

## 0.2.0 (04.11.2026) — в стиле Венчика

- **Без `Shell_TrayWnd`:** автоскрытие родной панели — `ABM_SETSTATE` без окна (как блок 1 клиента). Весь код — только документированные API.
- Цвета — из темы панели Ven4Tools (9 тем). «Пуск» — голова Венчика, над ним ушки (прозрачная полоса окна, не резервируется в рабочей области).
- Окна — значками по центру, под активным полоска акцента, при наведении миниатюра.
- `--left` — вертикальная панель у левого края (`ABE_LEFT`): панель слева, которой у родной панели Windows 11 нет.
- Щелчок по панели не забирает передний план (`WS_EX_NOACTIVATE`) — повторный щелчок по активному окну сворачивает его.
- Мягкое закрытие (`WM_CLOSE`) — уборка (`ABM_REMOVE`, возврат автоскрытия) и выход из программы.
- «Пуск» открывает «Свой Пуск» (Ven4Start рядом) ровно над собой.
- Проверено в ВМ: Win11 25H2 16/16, Win10 22H2 16/16 (`tests/BarUiDriver`: снизу и слева, окна, сворачивание, «Пуск», полный экран, WM_CLOSE, возврат родной панели), ЦП в простое 0–0,08 %.
- Известное ограничение: родная панель в автоскрытии выезжает, если мышь упирается в самый край экрана, где стоит её полоса (обычно нижний). Документированного способа совсем выключить родную панель нет.
