# Свой Пуск (Ven4Start) — заготовка «на полку»

Отдельный exe (.NET 10, WPF), в клиент Ven4Tools **не встроен**. Своё меню программ поверх
Windows: родной Пуск не трогается вообще, в explorer ничего не внедряется. Используются
только документированные Windows API.

## Что умеет

- **Окно меню** без рамки, по центру у нижнего края рабочей области того монитора, где мышь
  (`GetCursorPos` → `MonitorFromPoint` → `GetMonitorInfo`, масштаб — `GetDpiForMonitor`,
  манифест PerMonitorV2). Закрывается при потере фокуса и по Esc.
- **Все программы, включая приложения Store**: `SHGetKnownFolderItem(FOLDERID_AppsFolder)` →
  `IShellItem::BindToHandler(BHID_EnumItems)` → `IEnumShellItems`. Интерфейсы COM объявлены
  в `ShellApps.cs`. Название — `SIGDN_NORMALDISPLAY`, идентификатор — `SIGDN_PARENTRELATIVEPARSING`
  (для приложений Store это AppUserModelID, для обычных программ — путь/AUMID).
- **Запуск** — `ShellExecute("shell:AppsFolder\<идентификатор>")`.
- **Поиск** по названию (сначала совпадения с начала названия). Enter — запуск выбранного
  (по умолчанию первого) результата, ↑/↓ — выбор, двойной щелчок — запуск.
- **Быстрые действия**: блокировка (`LockWorkStation`), сон (`SetSuspendState`),
  перезагрузка и выключение (`ExitWindowsEx` + право `SeShutdownPrivilege`). Для сна,
  перезагрузки и выключения — подтверждение внутри окна (не MessageBox).
- **Горячая клавиша** Ctrl+Alt+Пробел (`RegisterHotKey`, окно-приёмник message-only). Если
  сочетание занято — всплывающая подсказка в трее.
- **Флаг `--win-key`**: одиночное нажатие-отпускание Win открывает меню (`SetWindowsHookEx(WH_KEYBOARD_LL)`).
  Нажатие Win не глотается, поэтому все сочетания Win+X работают как обычно. Перед отпусканием
  одиночного Win посылается не назначенная клавиша 0xE8 (`SendInput`) — оболочка считает это
  сочетанием и родной Пуск не открывает. При полноэкранном окне на переднем плане
  (`SHQueryUserNotificationState` + сравнение с границами монитора) Win не перехватывается.
- **Сторож**: так как родной Пуск не изменяется, падение процесса ничего не ломает; хук
  клавиатуры система снимает сама. Необработанные ошибки пишутся в
  `%LOCALAPPDATA%\Ven4Start\crash.log`.
- **Трей**: значок (`System.Windows.Forms.NotifyIcon`), левый щелчок — меню, правый — «Открыть меню» / «Выход».
- **Лёгкость**: таймеров нет, в простое процесс только ждёт сообщений. Список программ кэшируется
  в памяти и в `%LOCALAPPDATA%\Ven4Start\apps.json`; при каждом открытии меню показывается кэш,
  а свежий список читается в фоне (отдельный STA-поток) и подменяет показанный.
- Один экземпляр (мьютекс `Local\Ven4Start.Single`).

## Чего нет (пока)

- Значков программ (план: `IShellItemImageFactory::GetImage`, с кэшем).
- Закреплённых программ, недавних файлов, папок пользователя, настроек.
- Автозапуска (план: ярлык в `shell:startup` или ключ `HKCU\...\Run` — по выбору пользователя).
- Своего значка приложения (сейчас системный `SystemIcons.Application`).
- Английского перевода (тексты только на русском).
- Проверки в ВМ: GUI на ПК разработчика не запускался, только сборка.

## Как собрать

```
cd Shelf\Ven4Start
dotnet build -c Release
```

SDK берётся из `global.json` в корне репозитория. Результат:
`Shelf\Ven4Start\bin\Release\net10.0-windows\Ven4Start.exe`.

Запуск: `Ven4Start.exe` (горячая клавиша Ctrl+Alt+Пробел) или `Ven4Start.exe --win-key`.

## Что доделать до выпуска

1. Прогон в ВМ (Windows 10 22H2 и 11): список программ и Store-приложений, запуск, поиск,
   несколько мониторов с разным масштабом, автоскрытие панели задач, панель задач сбоку/сверху
   (сейчас окно всегда у нижнего края рабочей области).
2. `--win-key`: проверить Win+D/E/R/L/X/Tab/стрелки, Win+Shift+S, удержание Win, игры в
   полноэкранном и «оконном без рамки» режиме, экран блокировки, окна с правами администратора
   (без повышения прав хук не видит ввод в них — это ожидаемо, задокументировать).
3. Передача фокуса при открытии из хука: проверить, что окно реально становится активным
   (`SetForegroundWindow` разрешён процессу, получившему последнее событие ввода; при
   необходимости — документированный `AllowSetForegroundWindow`/выбор другого подхода).
4. Значки, закреплённые программы, автозапуск, настройки (сочетание клавиш, флаг Win).
5. Свой значок и оформление в стиле Ven4Tools, тёмная/светлая тема по системе.
6. Перевод строк, подпись exe, решение — отдельный пакет в каталоге или модуль клиента.
7. Посмотреть потребление памяти в простое (WPF + WinForms ради NotifyIcon; при желании —
   заменить на прямой `Shell_NotifyIcon`).
